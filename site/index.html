Program every radio you own from one channel list.

rflib keeps your repeaters, simplex, weather, and calling channels in one place, and writes each radio's programming file for CHIRP or the maker's software. When a repeater changes its tone, every radio that uses it knows.

Stop keeping a spreadsheet per radio

Most hams program each radio on its own: a CHIRP file for the handheld, the maker's software for the mobile, and a notebook of repeater tones. rflib makes the channels the thing you keep, and the radios something you build from them.

One list, every radio

Collect channels once: your own, and a shared list of repeaters, simplex, weather, and calling frequencies. Build each radio from searches, such as "repeaters within 45 km" or "NOAA weather", in sections you lay out.

It knows what's out of date

When a shared repeater changes its tone, goes off the air, or is retired, every radio that uses it shows it needs programming, and each radio's revisions say what changed since you last programmed it.

Your radio's own software

rflib writes the file your radio's software reads: CHIRP, Yaesu ADMS, or the maker's app. Names are fitted to each radio's display, power and transmit limits follow the rules, and a radio's file can be compared with rflib to see what changed on the radio.

What it doesn't do yet

rflib is in public preview. It programs real radios, but it's early. Today:

  • Analog only: FM, AM, SSB, and CW. Digital modes such as DMR, D-STAR, and Fusion aren't supported.
  • US rules: the shared list, band plans, and power limits follow the FCC's.
  • It writes the file; you load it into the radio with CHIRP or the maker's software.
  • A handful of radios are built in; others go through CHIRP unchecked until a model is added.

The full list is in the known limitations. Questions and radio requests go on GitHub.
